# GShare 설계 문서

## 컬러 토큰과 UI 컴포넌트 계약

현재 사용자 화면은 `src/app.css`의 `GShare light lime` 토큰을 단일 기준으로 사용한다.
밝은 회색 배경과 흰색 표면을 기본으로 두고 라임색은 주요 확인 동작, 현재 메뉴, 선택된
파일에만 사용한다. 장식용 gradient, 과도한 둥근 카드, 화면 진입 모션은 사용하지 않는다.

공통 컨트롤은 `src/lib/components/ui/`의 shadcn 스타일 컴포넌트를 사용한다. `Button`의
`default`, `outline`, `ghost`, `destructive` variant는 기존 primary/secondary/text/danger
버튼과 대응하며, Dialog와 ContextMenu는 Radix의 focus 관리와 키보드 동작을 보존한다.
파일 아이콘과 파일 작업 모델은 도메인 컴포넌트로 유지하고 공통 토큰만 사용한다.

정확한 값과 미리보기는 [`design-tokens.json`](./design-tokens.json)과
[`design-preview.html`](./design-preview.html)에 기록한다.

## 범위

이 MVP는 하나의 Google Drive 소유자 아래에 사용자별 개인 공간과 명시적 폴더 공유를 제공한다.
제3자는 Google Drive에 직접 권한을 받지 않고, Cloudflare Worker가 제공하는 애플리케이션 ACL을 통해 파일을 관리한다.

## 요청 흐름

### 관리자 가입과 로그인

1. bootstrap 스크립트가 허용된 관리자 Google 이메일 목록을 Worker secret으로 등록한다.
2. `/setup`이 `/api/auth/google/start`로 이동해 Google OAuth를 시작하고, 허용 목록에 있는 계정만 첫 관리자 및 이후 관리자 로그인에 사용할 수 있다.
3. Google refresh token은 Drive 연결 설정에도 암호화해 저장한다. 일반 사용자의 Google 신규 가입은 차단한다.

OAuth state와 `bootstrap`/`login`/`connect` 모드는 D1 전역 설정이 아니라 10분짜리 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키에 저장한다. 따라서 서로 다른 브라우저의 동시 로그인 요청이 state를 덮어쓰지 않는다. Cloudflare 정적 자산 라우팅보다 API Worker가 먼저 실행되도록 `/api/*`는 `assets.run_worker_first`로 고정한다.

### 사용자 가입과 로그인

1. 관리자가 `/api/invitations`로 일반 사용자용 일회성 초대 링크를 만든다.
2. 사용자가 `/invite/<token>`에서 표시 이름, ID, 비밀번호를 입력한다.
3. Better Auth username/password 계정을 만들고, Drizzle adapter를 통해 D1의 account 테이블에 비밀번호를 저장한다. D1 배치 트랜잭션에서 도메인 사용자 생성과 초대키 `used_at` 기록을 함께 수행하므로 같은 키로 두 번째 계정을 만들 수 없다.
4. 초대 계정은 패스키 없이도 즉시 active가 되고 Better Auth session cookie가 발급된다. 패스키는 가입 후 **내 정보**에서 선택적으로 등록한다.
5. 이후 사용자는 ID·비밀번호 또는 등록한 패스키 중 하나로 로그인한다. 로그인 호환 경로는 연결된 `auth_account`의 credential password를 기준으로 검증하고, 연결 계정에 credential이 없을 때만 기존 `users.password_hash`를 fallback으로 사용한 뒤 레거시 `gdrive_session`을 발급한다. 내 정보에서는 자신의 패스키를 등록하거나 제거할 수 있다. 패스키 제거 시 서버에서 credential을 폐기한 뒤, 지원 브라우저에는 WebAuthn Level 3 `signalAllAcceptedCredentials()`로 현재 유효한 credential 목록을 인증기에 전달한다. 지원하지 않는 브라우저·OS에서는 기기 패스키 관리자에서 직접 삭제해야 한다.
6. 로그아웃은 Better Auth 세션과 레거시 `gdrive_session`을 같은 요청에서 모두 종료한다. 이후에는 브라우저 history 대신 `replace`로 로그인 화면을 열어, 뒤로 가기나 새로고침으로 이전 작업공간이 다시 표시되지 않게 한다.

### 내 정보와 프로필 수정

내 정보 모달에서는 공개 핸들네임, 아바타 이미지, 비밀번호를 수정할 수 있다. 표시 닉네임은 별도 사용자 식별 정보로 노출하지 않는다. 핸들네임은 `normalizeLoginId` 규칙으로 정규화하고 `users.handle`의 고유 인덱스로 중복을 거부한다. 로그인 아이디는 가입 후 고정되며 내 정보에서만 마스킹 상태로 표시하고 클릭 시 잠시 원문을 확인할 수 있다. 아바타는 PNG/JPG/WEBP/GIF, 1MB 이하만 허용하며 검증된 data URL을 `users.avatar_url`에 저장해 인증된 사용자 화면에만 표시한다. 사용자 아바타가 비어 있으면 로그인 아이디를 우선으로 Google subject 또는 내부 사용자 ID를 대체 키로 사용하고, SHA-256 해시에서 색상과 좌우 대칭 패턴을 계산한 로컬 SVG identicon을 자동 생성해 저장한다. 따라서 완전한 난수가 아니라 사용자별로 일관된 기본 프로필이 만들어지며 원본 식별자는 외부 아바타 서비스로 전송하지 않는다.

비밀번호 변경은 현재 비밀번호를 확인한 뒤 새 비밀번호를 저장한다. Better Auth에 연결된 계정은 Better Auth의 `changePassword`를 사용하고, 레거시 계정은 동일한 PBKDF2 해시 규칙으로 `users.password_hash`를 갱신한다. 프로필 API는 same-origin과 현재 세션을 모두 확인한다.

### 비밀번호 변경 요청

관리자는 **멤버 관리** 화면에서 멤버별 활성화·비활성화와, 사용자의 분실 요청 없이도 1시간 유효한 일회성 변경 링크 직접 발급을 처리한다. 사용자는 로그인 화면에서 ID로 변경 요청을 만들 수도 있으며, 이 요청은 멤버 관리 화면의 **분실 요청** 목록에서 처리한다. 직접 발급과 요청 처리 모두 기존 미사용 링크를 폐기하고 새 링크를 발급하며, 링크 원문은 응답 시에만 노출하고 D1에는 해시만 저장한다. 직접 발급은 감사 로그에 기록된다.

`/reset/<token>`은 서버에서 토큰의 미사용·미만료·활성 계정 여부를 먼저 확인한다. 유효한 경우에만 대상 계정의 `@핸들`과 로그인 ID를 보여 주고 비밀번호 입력 폼을 렌더링한다. 표시 이름은 이 화면에 노출하지 않는다. 만료되었거나 이미 사용된 토큰은 입력 폼 없이 만료 안내만 표시한다. 변경 API는 사용 시각이 비어 있고 만료되지 않은 링크를 조건부로 점유하므로 동일 토큰을 동시에 제출해도 한 요청만 성공한다.

### Google 연결

관리자만 Google OAuth를 시작한다. 최초 관리자 등록과 관리자가 명시적으로 Drive를 다시 연결할 때에만 `drive.file` 및 `drive.readonly` 권한과 `prompt=consent`를 요청하고 refresh token을 암호화해 D1에 저장한 뒤 `GDrive Share` 폴더를 생성한다. `drive.file`은 앱이 만든 파일의 쓰기 권한으로, `drive.readonly`는 Drive에 이미 있던 파일의 본문 다운로드를 위한 읽기 권한으로 사용한다. callback은 Google이 확인한 이메일(`email_verified`)과 `GOOGLE_ADMIN_EMAILS`를 모두 확인하고, Drive 재연결은 현재 관리자 계정의 기존 Google subject와 일치해야 한다. 이후 관리자의 로그인은 OpenID·이메일 확인만 사용하므로, Google에서 이미 승인된 계정은 추가 권한 동의 없이 앱 세션만 새로 만든다.
멤버의 브라우저에는 Google token을 전달하지 않는다.

### 개인 공간과 폴더 공유

첫 파일 조회·업로드 시 `user_spaces`가 사용자별 Drive 루트 폴더를 `GDrive Share` 앱 루트 아래에 만든다. 기본 목록과 업로드 대상은 언제나 이 개인 루트이므로 다른 사용자의 파일이 섞이지 않는다.

폴더 소유자와 관리자는 폴더 행의 **공유 관리** 버튼에서 현재 공유 대상과 `pending` 초대를 확인하고, `@핸들네임`으로 활성 사용자를 추가·제거하거나 사용자별 `viewer`/`editor` 권한을 지정해 저장한다. 신청은 `folder_share_invitations`의 `pending` 상태로 저장되며, 수신자가 사이드바 알림에서 수락한 뒤에만 `folder_shares` ACL이 생성된다. 관리자는 사용자 개인 공간을 연 뒤에도 동일한 공유 관리 기능을 사용한다. 소유자는 수락 전에도 자신의 폴더에 파일을 올릴 수 있고, 수락 후 공유자는 사이드바의 **공유 폴더**에서 같은 폴더와 하위 파일을 본다. 공유 폴더 목록에는 수신 폴더뿐 아니라 내가 공유한 폴더도 함께 표시하고, 공유 대상 수와 일부 이름을 간단히 노출한다. 내가 공유한 폴더는 라임색 좌측 표시와 `공유 중` 표식으로 구분한다. `viewer`는 조회·다운로드만, `editor`는 업로드·폴더 생성·이름 변경·삭제까지 수행한다. 파일 목록은 파일별 업로더와 업로드 시각을 표시한다.

파일 이동·휴지통 이동·복구·영구 삭제는 목록 전체를 잠그지 않는다. 브라우저는 요청을 즉시 시작하고, 처리 중인 파일 ID만 `pendingOperationIds`로 표시해 해당 파일의 중복 작업과 드래그를 막는다. 나머지 파일의 선택·미리보기·이름 변경·이동은 계속 사용할 수 있다. 요청이 끝나면 캐시를 비우고 현재 목록을 백그라운드에서 갱신하며, 실패 시 오류 메시지를 표시한다. 다중 삭제와 다중 이동 요청은 항목별 요청을 병렬로 처리해 한 항목의 지연이 다른 항목의 상호작용을 막지 않도록 한다.

수신 대기 중인 신청은 사이드바의 별도 **공유 요청** 탭에서 수락·거절한다. 대기 요청 수가 있으면 프로필 아바타 위에 짧은 알림 배너를 표시하고, 배너와 탭 모두 같은 요청 처리 화면으로 이동한다. 공유 중인 폴더는 수신자와 대기 신청이 모두 제거되어 공유가 해제되기 전까지 휴지통으로 이동할 수 없다. 이 규칙은 UI에서 삭제 버튼을 대체하는 것과 별개로 `DELETE /api/files/:id`에서도 검사한다.

Drive 파일 ID와 논리 소유자는 D1의 `drive_files.owner_user_id`에 기록한다. 모든 목록·다운로드·미리보기·이름 변경·삭제·복구·업로드 요청은 파일 또는 조상 폴더의 소유권/공유 ACL을 검사한다. 따라서 사용자가 임의의 Drive file ID를 제출해 다른 사용자의 파일을 읽을 수 없다.

관리자는 개인 파일 공간을 갖거나 직접 업로드하지 않는다. 관리자 홈은 활성 멤버의 이미 생성된 개인 공간을 보여주는 운영 콘솔이며, 각 공간 안에서 파일 조회·다운로드·이름 변경·삭제·복구만 수행한다. 관리자 API 권한은 파일 ACL의 `admin`으로 별도 표시하고, 업로드 세션 생성과 폴더 생성 API는 관리자 요청을 `403`으로 거부한다.

### resumable upload

업로드 대상 폴더에 같은 이름의 일반 파일이 있으면 브라우저는 업로드 전 **건너뛰기**, **새 파일로 교체**(기존 파일을 휴지통으로 이동), **덮어쓰기**(기존 Drive 파일 ID 유지)를 선택하게 한다. 여러 충돌에는 선택을 일괄 적용할 수 있다.

```text
browser ── POST session ──> Worker ── create resumable session ──> Drive
browser ── PUT chunk ─────> Worker ── PUT session URL ───────────> Drive
browser <─ progress JSON ─ Worker <─ 308 Range / 200 file ─────── Drive
```

브라우저는 8MiB chunk를 256KiB 배수로 전송한다. Worker는 incoming `ReadableStream`을 Drive 요청 body로 전달하며 전체 파일을 버퍼링하지 않는다.
클라이언트가 확인한 충돌 외에도 업로드 세션 생성 시 Worker가 같은 상위 폴더의 파일명을 다시 검사한다. 충돌이
발견되면 기존 파일 ID와 이름을 포함한 `409` 응답을 반환하고, 브라우저는 같은 충돌 선택지로 다시 연결한다.
한 번의 선택·드롭에 같은 파일명이 여러 번 포함되면 첫 파일만 업로드하고 이후 중복 항목은
무시하여 동시 업로드로 인한 불필요한 `409`가 발생하지 않게 한다.

### 공유 링크

소유자 또는 편집 권한 사용자는 파일 행의 `공유 링크`로 읽기 전용 공개 미리보기 링크를 만들 수
있다. 링크 원문은 클립보드에 복사되고, 서버에는 SHA-256 토큰 해시만 저장한다. 링크 요청은
로그인 없이 토큰과 활성 파일을 확인한 뒤 미리보기 화면을 열며, 화면 안에서만 다운로드를 실행한다.
이미지·동영상·오디오·PDF·텍스트를 미리볼 수 있고, 휴지통 이동 또는 링크 해제 후에는 사용할 수
없다. 폴더 링크와 만료 시간은 현재 범위에 포함하지 않는다.
공개 링크와 인증 파일 응답에는 `no-store`, `nosniff`, `no-referrer`를 적용하며, inline 텍스트는
`text/plain`으로 내려 HTML·스크립트 실행을 막는다. HTML 문서 응답은 frame embedding을 거부한다.

## D1 불변식

- Better Auth의 `auth_user`, `auth_account`, `auth_session`, `auth_verification`, `auth_passkey`는 Drizzle schema와 동일해야 한다.
- 서비스 도메인의 `users`, `invitations`, `user_spaces`, `folder_shares`, `drive_files`, `upload_sessions`, `settings`, `audit_events`, 비밀번호 재설정 테이블도 같은 Drizzle schema에 등록한다. 공유 목록 원자 교체처럼 Drizzle의 단일 문장으로 표현하기 어려운 작업만 D1 `batch()` prepared statement로 실행한다.
- `users.auth_user_id`는 Better Auth 사용자와 서비스 ACL 사용자를 연결한다.
- `users.handle`은 가입 시 정규화한 고유 핸들이며, 데이터베이스 unique index로 중복을 막는다. 화면에서는 입력 없이 `@handle` 형식으로 표시하고, 기존 `login_id`가 있는 계정은 마이그레이션 시 핸들로 backfill한다.
- `users.avatar_url`은 허용된 이미지 data URL 또는 `NULL`만 저장하며, 프로필 수정 API가 MIME과 크기를 검증한다.

- `users.status = disabled`인 사용자는 session이 있어도 모든 보호 API에서 거부한다.
- `users.role = admin`은 Google account를 가져야 하며 ID·비밀번호 가입으로 생성할 수 없다.
- `users.role = member`는 초대 링크를 통해서만 생성된다.
- `invitations.token_hash`만 저장한다.
- `password_reset_links.token_hash`만 저장하고, 링크는 1시간 후 또는 사용 즉시 폐기한다.
- WebAuthn challenge는 5분 후 삭제한다.
- `upload_sessions.drive_session_url`은 암호화된 값으로만 저장한다.
- `drive_files`에 없는 파일 ID는 다운로드·변경할 수 없다.
- `user_spaces.user_id`는 사용자당 하나의 개인 Drive 루트만 가진다.
- `user_spaces.root_drive_id`인 개인 공간 루트는 어떤 역할도 이름 변경하거나 휴지통으로 이동할 수 없다. 관리자 목록에서는 선택·작업 메뉴 없이 공간 열기만 제공한다.
- `folder_shares(folder_drive_id, user_id)`는 중복될 수 없으며 공유자는 `viewer` 또는 `editor` 권한을 가진다. 수락 전 신청은 `folder_share_invitations`에만 존재한다.
- 같은 상위 폴더에서는 대소문자를 구분하지 않는 동일 이름의 활성 폴더를 만들 수 없다. 생성 버튼은 요청이 끝날 때까지 비활성화하고 서버도 다시 검사한다.

## 실패 처리

- Drive `308`: 마지막 Range 다음 byte부터 재개한다.
- Drive `5xx`: 브라우저가 같은 chunk를 최대 3회 exponential backoff로 재시도한다.
- upload session `404`: 세션을 실패 처리하고 사용자가 처음부터 다시 올린다.
- access token 만료: 저장된 refresh token으로 자동 갱신한다. refresh token 자체가 폐기되면 관리자에게 Google Drive 재연결을 안내한다.
- 비밀번호 분실: 사용자가 요청을 만들고 관리자가 일회성 변경 링크를 전달한다.
- 비어 있는 공간: 첫 업로드를 유도하는 empty state를 표시한다.
- 휴지통 파일: `updated_at`이 휴지통 이동 시각을 나타내며, 휴지통 화면에서 editor가 직접 영구 삭제할 수 있다. 폴더 영구 삭제는 Drive와 D1의 하위 휴지통 항목도 함께 정리한다. Cloudflare Cron은 매일 03:00 KST에 7일 지난 Drive 파일을 영구 삭제한 뒤 D1 메타데이터를 제거한다. Drive 삭제가 실패하면 D1 행을 남겨 다음 실행에서 재시도한다.

## 작업공간 UI 원칙

### React Router 인증 화면

인증 진입 화면은 파일 작업공간의 밝은 회색 캔버스와 라임색 핵심 동작을 공유한다. 데스크톱에서는
브랜드·제품 설명 패널과 로그인 패널을 나란히 배치하고, 모바일에서는 설명 패널을 먼저 보여준
뒤 로그인 폼을 이어 붙인다. Google OAuth는 라임색 주 동작으로, 아이디 로그인은 보조 동작으로
구분한다. 입력 오류는 폼 안에서 즉시 읽을 수 있는 오류 블록으로 표시하며, 모바일에서 수평
overflow가 생기지 않아야 한다. `prefers-reduced-motion`과 키보드 focus ring은 전역 스타일 계약에
포함한다.

- 파일을 올리고 찾고 관리하는 흐름을 한 화면에 유지한다. 작업공간 메뉴는 상단에 한 번만 두고, 화면 전체 폭을 현재 폴더와 파일 목록에 집중한다.
- 업로드 영역은 파일을 끌어오는 동안 현재 위치 또는 선택한 폴더를 알려주는 드롭 오버레이로 확장된다. 드래그 앤 드롭, 다중 파일 선택, 붙여넣기 업로드를 같은 흐름으로 안내한다.
- 밝은 회색 캔버스(`#F7F9F5`) 위에 흰색 표면과 라임색 강조(`#B8DC3B`)를 사용한다. 라임색은 업로드, 선택된 파일, 포커스와 핵심 확인 동작에만 사용한다.
- 폴더 생성·이름 변경·공유 설정은 동일한 모달 구조(설명, 명시적 필드 라벨, 취소와 확인 버튼)로 제공한다. 입력 컨트롤은 흰색 표면과 명확한 테두리를 사용한다.
- 파일 행의 관리 동작은 항상 보이고, hover/focus에서는 배경과 글자색으로 더 선명하게 표시한다. 키보드 포커스와 reduced-motion 환경을 유지한다.

### 업로드 이름 충돌

- 충돌 모달은 처리 대상 파일명을 별도 정보 블록으로 먼저 보여 주고, 단순히 같은 이름이 있다는 사실과 사용자가 결정해야 할 행동을 분리해 설명한다.
- `건너뛰기`, `새 파일로 교체`, `덮어쓰기`는 각각 결과를 한 줄로 명시한 세로 선택지로 제공한다. `새 파일로 교체`는 기존 파일을 휴지통으로 옮긴 뒤 새 파일을 만드는 동작이고, `덮어쓰기`는 기존 Drive 파일 ID를 유지하고 내용만 바꾸는 동작이다.
- 여러 충돌의 일괄 적용은 현재 파일 처리와 시각적으로 분리한다. 작은 화면에서는 일괄 처리 버튼을 세로로 배치해 레이블이 잘리거나 의도치 않게 누르는 일을 막는다.

### 파일 조작과 미디어 미리보기

- 파일 행은 우클릭(키보드에서는 `Shift+F10` 또는 컨텍스트 메뉴 키)으로 열기, 미리보기, 공유, 이름 변경, 다운로드, 휴지통 이동을 상황에 맞게 제공한다. 휴지통에서는 복구와 영구 삭제를 제공한다.
- 목록의 이미지와 동영상은 인증된 `/api/files/:id/thumbnail` 프록시를 사용한다. Google Drive가 제공하는 작은 `thumbnailLink`만 전달하므로 목록을 스크롤할 때 원본 미디어를 내려받지 않는다. 응답은 `private, max-age=86400, stale-while-revalidate=604800`으로 브라우저 캐시를 허용하고, 동영상에는 재생 표식을 더한다. 항목 클릭 또는 메뉴의 **미리보기**에서는 기존 `/api/files/:id/preview` 스트림으로 브라우저 기본 컨트롤을 가진 플레이어 모달을 연다.
- preview 응답은 이미지·동영상·PDF·텍스트만 inline으로 전달하며, 모든 응답은 기존 파일 ACL 검사와 `private, no-store` 캐시 정책을 유지한다. 서버에서 별도의 썸네일 파일을 생성하거나 저장하지 않는다.

파일 행의 색상 토큰은 역할별로 분리한다. 폴더는 `--folder-*`의 따뜻한 주황색, 일반 파일은 `--file-*`의 슬레이트색, 이미지는 `--image-*`의 청록색, 동영상은 `--video-*`의 보라색을 사용해 아이콘 모양이 작아도 항목 유형을 구분할 수 있게 한다.

### 파일 드래그 이동

- 파일 행은 네이티브 드래그 소스로 사용한다. 체크박스·미리보기·작업 버튼에서 시작한 포인터 동작은 드래그로 해석하지 않아 자식 컨트롤의 기본 동작이 끊기지 않게 한다. 터치 포인터는 같은 이동 계약을 사용하는 포인터 드래그로 처리한다.
- 내부 드래그 타입(`application/x-gdrive-file`)에는 선택한 파일 ID 배열을 JSON으로 기록한다. 이동 대상은 화면의 드래그 상태와 `DataTransfer` 페이로드를 함께 사용해 판별하고, 이전 단일 ID 페이로드도 읽는다. 운영체제 파일 드롭 업로드와 같은 영역을 사용하지만 내부 드래그는 업로드 처리에서 제외한다.
- 운영체제 파일 드롭은 `copy` 대상으로 별도 표시하고, 내부 파일 이동은 `move` 대상으로 표시한다. 외부 파일을 폴더 위에 놓으면 해당 폴더에 업로드한다.
- 폴더 행과 현재 경로의 각 상위 폴더 버튼은 이동 대상일 때 초록색 상태와 `여기에 놓기` 안내를 표시한다. 경로의 원하는 상위 폴더에 놓으면 해당 폴더로 이동하며, 최상위 경로에 놓으면 개인 공간 루트로 이동한다.
- 이동은 기존 `PATCH /api/files/:id`의 `parentId` 경로를 사용한다. 대상 폴더에 대소문자를 구분하지 않는 같은 이름의 폴더가 있으면 이동을 `409`으로 거부한다. 여러 항목 중 일부가 실패하면 성공 항목만 현재 목록에서 제거하고 실패 항목은 그대로 두며, 성공·실패 개수와 첫 실패 원인을 표시한다. 서버의 파일·폴더 ACL 검사를 그대로 적용하며 개인 공간 간 또는 공유 권한 밖 이동은 거부한다.
- 폴더를 자기 자신 또는 자기 하위 폴더로 이동하는 순환 참조는 모킹과 서버에서 모두 거부한다.
- 드롭 대상 강조는 CSS 상태 스타일로 표시하며, 화면 진입 모션은 사용하지 않는다. 드래그 이벤트는 시각 효과와 분리되어야 한다.

#### 회귀 테스트 계약

- 선택한 여러 항목의 ID가 내부 MIME 페이로드로 왕복된다.
- 기존 단일 ID는 허용하지만 깨진 JSON과 문자열이 아닌 ID 배열은 거부한다.
- 현재 부모로의 이동과 폴더 자신에 대한 드롭은 네트워크 요청을 만들지 않는다.
- 선택된 항목이 없어도 드래그를 시작한 파일 하나를 이동 대상으로 사용한다.
- 다중 이동의 부분 실패에서는 성공·실패 항목이 분리된다.
- 스타일이 적용되지 않는 환경에서도 드래그 상호작용 로직은 예외를 내지 않는다.

### React Router 화면 회귀 범위

마이그레이션 이후에도 파일 목록은 업로드·선택/일괄 삭제·정렬·미리보기·휴지통 복구·영구 삭제를
제공해야 한다. 멤버 화면에는 공유 폴더와 공유 요청을, 관리자 화면에는 초대·멤버 상태
관리를 노출한다. 개발 환경의 `?mock=1` 모드는 인증·Drive 없이 같은 화면 전환과 업로드·
하위/상위 폴더 이동·폴더 공유 권한 저장·공유 폴더 목록 반영을 재현해 UI 회귀를 빠르게
확인하는 용도다. 관리자 화면에서 만든 모킹 초대·비밀번호 변경 링크도 `mock=1`을 유지해
가입·변경 폼 제출까지 로컬에서 재현한다. 검색 후 전체 선택·삭제·다운로드는 현재 화면에
보이는 목록만 대상으로 하며, 공유 사용자 검색은 오래된 응답이 최신 검색 결과를 덮어쓰지
않는다. 모킹 공유 데이터는 브라우저 메모리에서만 유지된다.

## 2026-08-20 작업공간 재설계

작업공간은 관리자 대시보드가 아니라 팀이 파일을 넘겨보는 작업실로 설계한다. 상단에는 짙은
녹색 제품 바와 현재 계정을 두고, 왼쪽에는 저장 공간·공유·요청·휴지통을 세로 작업 레일로
고정한다. 본문은 현재 위치와 다음 행동을 먼저 보여준 뒤, 파일 표에 가장 많은 폭을 사용한다.
둥근 카드와 장식용 그라디언트 대신 종이 같은 표면, 얇은 규칙선, 작은 모서리를 사용해 파일명과
행 작업이 시각적 우선순위를 갖게 한다.

업로드·폴더 생성·선택 작업·검색·정렬은 하나의 도구 표면에 배치하고, 행 작업은 항상 노출한다.
파일 행은 이름·종류·수정 시각·작업을 한 줄의 밀도로 유지하며, 선택된 행은 라임색 왼쪽 표식으로
구분한다. 폴더는 노란색, 이미지·영상·문서 등은 서로 다른 낮은 채도의 배지로 구분하되 장식보다
파일 유형 식별을 우선한다.

폴더 탐색에서는 현재 경로를 breadcrumb로 표시하고, 경로 왼쪽에 항상 **상위 폴더** 버튼을
둔다. 루트에서는 버튼을 비활성화하고, 하위 폴더에서는 한 단계씩 부모로 이동시켜 깊은 폴더에서도
저장 공간까지 돌아가는 방법을 화면 안에서 바로 찾을 수 있게 한다. 파일 행의 포인터 드래그는
체크박스·버튼·링크에서 시작하지 않도록 하여 폴더명 클릭, 미리보기, 다운로드 같은 기본 컨트롤을
드래그 로직이 가로채지 않는다. 폴더에 진입할 때 검색어와 선택 상태도 초기화하며, 현재 폴더를
연속으로 여는 입력은 무시해 breadcrumb에 같은 경로가 중첩되지 않게 한다.

색상은 `#F7F9F5` 캔버스, `#FFFFFF` 표면, `#18211B` 제품 바, `#B8DC3B` 작업 강조,
`#698A1B` 확인·포커스 신호를 기본으로 한다. Bricolage Grotesque는 제목에만, IBM Plex Sans는
본문에, IBM Plex Mono는 경로·상태·메타 정보에 사용한다. 파일 행 자체의 네이티브 드래그 계약,
키보드 focus ring, reduced-motion 대응은 유지한다. 960px 이하에서는 작업 레일을 두 줄 탐색으로
바꾸고 620px 이하에서는 긴 파일 표만 표 내부에서 스크롤한다.

## 2026-07-29 기능 중심 작업공간

작업공간의 단일 목적을 **현재 위치에서 파일을 찾고, 선택하고, 정리하는 것**으로 정했다.
큰 인사말은 제거하고 상단을 제품 식별과 현재 계정만 제공하는 낮은 전역 바로 바꿨다. 그 아래는
목적지 탐색, 현재 화면의 제목과 다음 행동, 폴더 경로, 생성·검색 도구, 선택 상태, 파일 목록
순서로 읽힌다. 탐색 버튼은 저장 공간·공유·요청·휴지통과 계정·새로고침을 두 그룹으로 분리한다.

화면별 제목과 설명은 `getWorkspacePresentation`에서 결정한다. 하위 폴더에서는 폴더명이 제목이
되고, 공유 요청과 휴지통에서는 사용자가 해야 할 검토·복구 행동을 설명한다. 현재 목록의 항목
수는 제목 오른쪽의 작은 유틸리티 표시로 제공하며 장식용 지표로 확장하지 않는다.

생성과 선택 작업은 `파일 작업 메뉴`라는 하나의 연결된 액션 그룹으로 제공한다. 업로드·새 폴더와
선택 다운로드·삭제는 같은 표면 안에서 현재 권한과 선택 상태에 따라 나타나며, 폴더 검색과 정렬은
오른쪽 컨트롤 그룹으로 분리한다. 선택 체크박스와 다중 선택 안내는 별도 상태 줄에서 유지한다. 선택된 행은
라임색 왼쪽 표식으로 구분하고 일괄 작업은 선택된 동안에만 표시한다. 파일 행의 기존
드래그·컨텍스트 메뉴·미리보기·공유·다운로드 동작은 유지한다.

목록을 백그라운드에서 갱신할 때 상태 메시지는 테이블의 고정된 상단 레이어로 표시한다. 갱신 시작과
완료 사이에 테이블 헤더와 파일 행의 위치가 바뀌지 않아야 하며, 기존 목록의 선택·작업 컨트롤은
계속 같은 위치에서 사용할 수 있어야 한다.

모바일에서는 제품 바를 한 줄로 유지하고 계정의 보조 텍스트를 숨긴다. 탐색 그룹은 가로
스크롤을 허용하고, 도구 표면은 생성 2열·검색 1열·정렬 2열로 재배치한다. 360px 화면에서 문서
수평 overflow가 없어야 하며 빈 상태와 파일 행 작업은 세로 흐름 안에서 계속 접근 가능해야 한다.

작업공간 캔버스와 파일 행 hover에는 장식용 그라데이션을 사용하지 않는다. 표면 모서리는
도구 모음·파일 표에서 `0.4rem`, 버튼·입력·파일 아이콘에서 `0.35rem` 이하로 유지한다. 원형
아바타와 상태 배지만 예외로 둔다.

파일 생성·검색 도구, 선택 상태, 안내, 폴더 경로, 파일 표는 하나의 `workspace-file-area` 표면으로
묶는다. 저장 공간 사용량은 목록과의 사이에 두지 않고 제목 오른쪽의 항목 요약에 함께 표시한다.

### 공유 폴더 최상위 목록

`공유 폴더` 최상위는 파일을 조작하는 목록이 아니라 공유된 폴더를 찾고 권한을 확인하는 색인이다.
따라서 선택 체크박스·선택 상태 줄·드래그 핸들은 표시하지 않는다. 각 행은 폴더 열기와 공유 관리만
제공하며, 내가 공유한 폴더에는 공유 인원과 일부 이름을 표시한다. 하위 폴더에 들어간 뒤에는 기존의
권한 기반 파일 작업·다중 선택·드래그 동작을 다시 제공한다.
