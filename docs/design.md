# GShare 설계 문서

## 범위

이 MVP는 하나의 Google Drive 소유자 아래에 사용자별 개인 공간과 명시적 폴더 공유를 제공한다.
제3자는 Google Drive에 직접 권한을 받지 않고, Cloudflare Worker가 제공하는 애플리케이션 ACL을 통해 파일을 관리한다.

## 요청 흐름

### 관리자 가입과 로그인

1. bootstrap 스크립트가 허용된 관리자 Google 이메일 목록을 Worker secret으로 등록한다.
2. `/setup`이 `/api/auth/google/start`로 이동해 Google OAuth를 시작하고, 허용 목록에 있는 계정만 첫 관리자 및 이후 관리자 로그인에 사용할 수 있다.
3. Google refresh token은 Drive 연결 설정에도 암호화해 저장한다. 일반 사용자의 Google 신규 가입은 차단한다.

OAuth state와 `bootstrap`/`login`/`connect` 모드는 D1 전역 설정이 아니라 10분짜리 `HttpOnly`, `Secure`, `SameSite=Lax` 쿠키에 저장한다. 따라서 서로 다른 브라우저의 동시 로그인 요청이 state를 덮어쓰지 않는다. Cloudflare 정적 자산 라우팅보다 API Worker가 먼저 실행되도록 `/api/*`는 `assets.run_worker_first`로 고정한다.

### 사용자 가입과 로그인

1. 관리자가 `/api/invitations`로 일반 사용자용 일회성 초대 링크를 만든다.
2. 사용자가 `/invite/<token>`에서 표시 이름, ID, 비밀번호를 입력한다.
3. Better Auth username/password 계정을 만들고, Drizzle adapter를 통해 D1의 account 테이블에 비밀번호를 저장한다. D1 배치 트랜잭션에서 도메인 사용자 생성과 초대키 `used_at` 기록을 함께 수행하므로 같은 키로 두 번째 계정을 만들 수 없다.
4. 초대 계정은 패스키 없이도 즉시 active가 되고 Better Auth session cookie가 발급된다. 패스키는 가입 후 **내 정보**에서 선택적으로 등록한다.
5. 이후 사용자는 ID·비밀번호 또는 등록한 패스키 중 하나로 로그인한다. 내 정보에서는 자신의 패스키를 등록하거나 제거할 수 있다. 패스키 제거 시 서버에서 credential을 폐기한 뒤, 지원 브라우저에는 WebAuthn Level 3 `signalAllAcceptedCredentials()`로 현재 유효한 credential 목록을 인증기에 전달한다. 지원하지 않는 브라우저·OS에서는 기기 패스키 관리자에서 직접 삭제해야 한다.
6. 로그아웃은 Better Auth 세션과 레거시 `gdrive_session`을 같은 요청에서 모두 종료한다. 이후에는 브라우저 history 대신 `replace`로 로그인 화면을 열어, 뒤로 가기나 새로고침으로 이전 작업공간이 다시 표시되지 않게 한다.

### 내 정보와 프로필 수정

내 정보 모달에서는 공개 핸들네임, 아바타 이미지, 비밀번호를 수정할 수 있다. 표시 닉네임은 별도 사용자 식별 정보로 노출하지 않는다. 핸들네임은 `normalizeLoginId` 규칙으로 정규화하고 `users.handle`의 고유 인덱스로 중복을 거부한다. 로그인 아이디는 가입 후 고정되며 내 정보에서만 마스킹 상태로 표시하고 클릭 시 잠시 원문을 확인할 수 있다. 아바타는 PNG/JPG/WEBP/GIF, 1MB 이하만 허용하며 검증된 data URL을 `users.avatar_url`에 저장해 인증된 사용자 화면에만 표시한다. 사용자 아바타가 비어 있으면 로그인 아이디를 우선으로 Google subject 또는 내부 사용자 ID를 대체 키로 사용하고, SHA-256 해시에서 색상과 좌우 대칭 패턴을 계산한 로컬 SVG identicon을 자동 생성해 저장한다. 따라서 완전한 난수가 아니라 사용자별로 일관된 기본 프로필이 만들어지며 원본 식별자는 외부 아바타 서비스로 전송하지 않는다.

비밀번호 변경은 현재 비밀번호를 확인한 뒤 새 비밀번호를 저장한다. Better Auth에 연결된 계정은 Better Auth의 `changePassword`를 사용하고, 레거시 계정은 동일한 PBKDF2 해시 규칙으로 `users.password_hash`를 갱신한다. 프로필 API는 same-origin과 현재 세션을 모두 확인한다.

### 비밀번호 변경 요청

관리자는 **멤버 관리** 화면에서 멤버별 활성화·비활성화와, 사용자의 분실 요청 없이도 1시간 유효한 일회성 변경 링크 직접 발급을 처리한다. 사용자는 로그인 화면에서 ID로 변경 요청을 만들 수도 있으며, 이 요청은 멤버 관리 화면의 **분실 요청** 목록에서 처리한다. 직접 발급과 요청 처리 모두 기존 미사용 링크를 폐기하고 새 링크를 발급하며, 링크 원문은 응답 시에만 노출하고 D1에는 해시만 저장한다. 직접 발급은 감사 로그에 기록된다.

`/reset/<token>`은 서버에서 토큰의 미사용·미만료·활성 계정 여부를 먼저 확인한다. 유효한 경우에만 대상 계정의 `@핸들`과 로그인 ID를 보여 주고 비밀번호 입력 폼을 렌더링한다. 표시 이름은 이 화면에 노출하지 않는다. 만료되었거나 이미 사용된 토큰은 입력 폼 없이 만료 안내만 표시한다. 변경 API는 사용 시각이 비어 있고 만료되지 않은 링크를 조건부로 점유하므로 동일 토큰을 동시에 제출해도 한 요청만 성공한다.

### Google 연결

관리자만 Google OAuth를 시작한다. 최초 관리자 등록과 관리자가 명시적으로 Drive를 다시 연결할 때에만 `drive.file` 및 `drive.metadata.readonly` 권한과 `prompt=consent`를 요청하고 refresh token을 암호화해 D1에 저장한 뒤 `GDrive Share` 폴더를 생성한다. `drive.metadata.readonly`는 상단에 Google Drive 전체 저장 공간의 사용량과 남은 공간을 표시하기 위한 최소 읽기 권한이다. 이후 관리자의 로그인은 OpenID·이메일 확인만 사용하므로, Google에서 이미 승인된 계정은 추가 권한 동의 없이 앱 세션만 새로 만든다.
멤버의 브라우저에는 Google token을 전달하지 않는다.

### 개인 공간과 폴더 공유

첫 파일 조회·업로드 시 `user_spaces`가 사용자별 Drive 루트 폴더를 `GDrive Share` 앱 루트 아래에 만든다. 기본 목록과 업로드 대상은 언제나 이 개인 루트이므로 다른 사용자의 파일이 섞이지 않는다.

폴더 소유자는 폴더 행의 **공유** 버튼에서 `@핸들네임`으로 활성 사용자를 검색하고 사용자별 `viewer`/`editor` 권한을 지정해 공유 신청을 보낸다. 신청은 `folder_share_invitations`의 `pending` 상태로 저장되며, 수신자가 사이드바 알림에서 수락한 뒤에만 `folder_shares` ACL이 생성된다. 소유자는 수락 전에도 자신의 폴더에 파일을 올릴 수 있고, 수락 후 공유자는 사이드바의 **공유 폴더**에서 같은 폴더와 하위 파일을 본다. `viewer`는 조회·다운로드만, `editor`는 업로드·폴더 생성·이름 변경·삭제까지 수행한다. 파일 목록은 파일별 업로더와 업로드 시각을 표시한다.

Drive 파일 ID와 논리 소유자는 D1의 `drive_files.owner_user_id`에 기록한다. 모든 목록·다운로드·미리보기·이름 변경·삭제·복구·업로드 요청은 파일 또는 조상 폴더의 소유권/공유 ACL을 검사한다. 따라서 사용자가 임의의 Drive file ID를 제출해 다른 사용자의 파일을 읽을 수 없다.

관리자는 개인 파일 공간을 갖거나 직접 업로드하지 않는다. 관리자 홈은 활성 멤버의 이미 생성된 개인 공간을 보여주는 운영 콘솔이며, 각 공간 안에서 파일 조회·다운로드·이름 변경·삭제·복구만 수행한다. 관리자 API 권한은 파일 ACL의 `admin`으로 별도 표시하고, 업로드 세션 생성과 폴더 생성 API는 관리자 요청을 `403`으로 거부한다.

### resumable upload

업로드 대상 폴더에 같은 이름의 일반 파일이 있으면 브라우저는 업로드 전 **건너뛰기**, **새 파일로 교체**(기존 파일을 휴지통으로 이동), **덮어쓰기**(기존 Drive 파일 ID 유지)를 선택하게 한다. 여러 충돌에는 선택을 일괄 적용할 수 있다.

```text
browser ── POST session ──> Worker ── create resumable session ──> Drive
browser ── PUT chunk ─────> Worker ── PUT session URL ───────────> Drive
browser <─ progress JSON ─ Worker <─ 308 Range / 200 file ─────── Drive
```

브라우저는 8MiB chunk를 256KiB 배수로 전송한다. Worker는 incoming `ReadableStream`을 Drive 요청 body로 전달하며 전체 파일을 버퍼링하지 않는다.

## D1 불변식

- Better Auth의 `auth_user`, `auth_account`, `auth_session`, `auth_verification`, `auth_passkey`는 Drizzle schema와 동일해야 한다.
- 서비스 도메인의 `users`, `invitations`, `user_spaces`, `folder_shares`, `drive_files`, `upload_sessions`, `settings`, `audit_events`, 비밀번호 재설정 테이블도 같은 Drizzle schema에 등록한다. 공유 목록 원자 교체처럼 Drizzle의 단일 문장으로 표현하기 어려운 작업만 D1 `batch()` prepared statement로 실행한다.
- `users.auth_user_id`는 Better Auth 사용자와 서비스 ACL 사용자를 연결한다.
- `users.handle`은 가입 시 정규화한 고유 핸들이며, 데이터베이스 unique index로 중복을 막는다. 화면에서는 입력 없이 `@handle` 형식으로 표시하고, 기존 `login_id`가 있는 계정은 마이그레이션 시 핸들로 backfill한다.
- `users.avatar_url`은 허용된 이미지 data URL 또는 `NULL`만 저장하며, 프로필 수정 API가 MIME과 크기를 검증한다.

- `users.status = disabled`인 사용자는 session이 있어도 모든 보호 API에서 거부한다.
- `users.role = admin`은 Google account를 가져야 하며 ID·비밀번호 가입으로 생성할 수 없다.
- `users.role = member`는 초대 링크를 통해서만 생성된다.
- `invitations.token_hash`만 저장한다.
- `password_reset_links.token_hash`만 저장하고, 링크는 1시간 후 또는 사용 즉시 폐기한다.
- WebAuthn challenge는 5분 후 삭제한다.
- `upload_sessions.drive_session_url`은 암호화된 값으로만 저장한다.
- `drive_files`에 없는 파일 ID는 다운로드·변경할 수 없다.
- `user_spaces.user_id`는 사용자당 하나의 개인 Drive 루트만 가진다.
- `user_spaces.root_drive_id`인 개인 공간 루트는 어떤 역할도 이름 변경하거나 휴지통으로 이동할 수 없다. 관리자 목록에서는 선택·작업 메뉴 없이 공간 열기만 제공한다.
- `folder_shares(folder_drive_id, user_id)`는 중복될 수 없으며 공유자는 `viewer` 또는 `editor` 권한을 가진다. 수락 전 신청은 `folder_share_invitations`에만 존재한다.
- 같은 상위 폴더에서는 대소문자를 구분하지 않는 동일 이름의 활성 폴더를 만들 수 없다. 생성 버튼은 요청이 끝날 때까지 비활성화하고 서버도 다시 검사한다.

## 실패 처리

- Drive `308`: 마지막 Range 다음 byte부터 재개한다.
- Drive `5xx`: 브라우저가 같은 chunk를 최대 3회 exponential backoff로 재시도한다.
- upload session `404`: 세션을 실패 처리하고 사용자가 처음부터 다시 올린다.
- refresh token 만료: 관리자에게 Google Drive 재연결을 안내한다.
- 비밀번호 분실: 사용자가 요청을 만들고 관리자가 일회성 변경 링크를 전달한다.
- 비어 있는 공간: 첫 업로드를 유도하는 empty state를 표시한다.
- 휴지통 파일: `updated_at`이 휴지통 이동 시각을 나타내며, Cloudflare Cron이 매일 03:00 KST에 7일 지난 Drive 파일을 영구 삭제한 뒤 D1 메타데이터를 제거한다. Drive 삭제가 실패하면 D1 행을 남겨 다음 실행에서 재시도한다.

## 작업공간 UI 원칙

- 파일을 올리고 찾고 관리하는 흐름을 한 화면에 유지한다. 좌측은 개인 공간·공유 폴더·휴지통만 담는 얇은 내비게이션이고, 중앙은 현재 폴더와 파일 목록에 집중한다.
- 업로드 영역은 화면에서 가장 먼저 보이는 확장형 드롭 스트립이다. 드래그 앤 드롭, 다중 파일 선택, 붙여넣기 업로드를 같은 흐름으로 안내한다.
- 검은 캔버스(`#0B0D0F`) 위에 한 단계 밝은 표면과 구리색 강조(`#E8AA70`)만 사용한다. 구리색은 업로드, 선택된 파일, 핵심 확인 동작에만 사용한다.
- 폴더 생성·이름 변경·공유 설정은 동일한 모달 구조(설명, 명시적 필드 라벨, 취소와 확인 버튼)로 제공한다. 브라우저 기본 흰색 입력 컨트롤을 사용하지 않는다.
- 파일 행의 관리 동작은 항상 식별 가능해야 하며, hover/focus에서는 더 선명하게 표시한다. 키보드 포커스와 reduced-motion 환경을 유지한다.

### 업로드 이름 충돌

- 충돌 모달은 처리 대상 파일명을 별도 정보 블록으로 먼저 보여 주고, 단순히 같은 이름이 있다는 사실과 사용자가 결정해야 할 행동을 분리해 설명한다.
- `건너뛰기`, `새 파일로 교체`, `덮어쓰기`는 각각 결과를 한 줄로 명시한 세로 선택지로 제공한다. `새 파일로 교체`는 기존 파일을 휴지통으로 옮긴 뒤 새 파일을 만드는 동작이고, `덮어쓰기`는 기존 Drive 파일 ID를 유지하고 내용만 바꾸는 동작이다.
- 여러 충돌의 일괄 적용은 현재 파일 처리와 시각적으로 분리한다. 작은 화면에서는 일괄 처리 버튼을 세로로 배치해 레이블이 잘리거나 의도치 않게 누르는 일을 막는다.

### 파일 조작과 미디어 미리보기

- 파일 행은 우클릭(키보드에서는 `Shift+F10` 또는 컨텍스트 메뉴 키)으로 열기, 미리보기, 공유, 이름 변경, 다운로드, 휴지통 이동을 상황에 맞게 제공한다. 휴지통에서는 복구만 제공한다.
- 목록의 이미지와 동영상은 인증된 `/api/files/:id/thumbnail` 프록시를 사용한다. Google Drive가 제공하는 작은 `thumbnailLink`만 전달하므로 목록을 스크롤할 때 원본 미디어를 내려받지 않는다. 응답은 `private, max-age=86400, stale-while-revalidate=604800`으로 브라우저 캐시를 허용하고, 동영상에는 재생 표식을 더한다. 항목 클릭 또는 메뉴의 **미리보기**에서는 기존 `/api/files/:id/preview` 스트림으로 브라우저 기본 컨트롤을 가진 플레이어 모달을 연다.
- preview 응답은 이미지·동영상·PDF·텍스트만 inline으로 전달하며, 모든 응답은 기존 파일 ACL 검사와 `private, no-store` 캐시 정책을 유지한다. 서버에서 별도의 썸네일 파일을 생성하거나 저장하지 않는다.

파일 행의 색상 토큰은 역할별로 분리한다. 폴더는 `--folder-*`의 따뜻한 주황색, 일반 파일은 `--file-*`의 슬레이트색, 이미지는 `--image-*`의 청록색, 동영상은 `--video-*`의 보라색을 사용해 아이콘 모양이 작아도 항목 유형을 구분할 수 있게 한다.

### 파일 드래그 이동

- 파일 행 왼쪽의 `⠿` 핸들만 네이티브 드래그 소스로 사용한다. 체크박스·미리보기·작업 버튼과 드래그 시작 영역을 분리해 브라우저가 자식 컨트롤의 포인터 동작을 우선 처리해도 드래그가 끊기지 않게 한다.
- 내부 드래그 타입(`application/x-gdrive-file`)에는 선택한 파일 ID 배열을 JSON으로 기록한다. 이동 대상은 화면의 드래그 상태와 `DataTransfer` 페이로드를 함께 사용해 판별하고, 이전 단일 ID 페이로드도 읽는다. 운영체제 파일 드롭 업로드와 같은 영역을 사용하지만 내부 드래그는 업로드 처리에서 제외한다.
- 폴더 행과 현재 경로의 각 상위 폴더 버튼은 이동 대상일 때 초록색 상태와 `여기에 놓기` 안내를 표시한다. 경로의 원하는 상위 폴더에 놓으면 해당 폴더로 이동하며, 최상위 경로에 놓으면 개인 공간 루트로 이동한다.
- 이동은 기존 `PATCH /api/files/:id`의 `parentId` 경로를 사용한다. 여러 항목 중 일부가 실패하면 성공 항목만 현재 목록에서 제거하고 실패 항목은 그대로 두며, 성공·실패 개수와 첫 실패 원인을 표시한다. 서버의 파일·폴더 ACL 검사를 그대로 적용하며 개인 공간 간 또는 공유 권한 밖 이동은 거부한다.
- 드롭 대상 강조 효과는 표준 Web Animations API를 사용하고, API가 없거나 애니메이션 생성이 실패해도 드래그 이벤트를 중단하지 않는다.

#### 회귀 테스트 계약

- 선택한 여러 항목의 ID가 내부 MIME 페이로드로 왕복된다.
- 기존 단일 ID는 허용하지만 깨진 JSON과 문자열이 아닌 ID 배열은 거부한다.
- 현재 부모로의 이동과 폴더 자신에 대한 드롭은 네트워크 요청을 만들지 않는다.
- 다중 이동의 부분 실패에서는 성공·실패 항목이 분리된다.
- 애니메이션 미지원 환경에서도 드래그 상호작용 로직은 예외를 내지 않는다.
